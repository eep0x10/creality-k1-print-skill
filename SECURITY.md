# Security and hardware-affecting reports

Do not test a suspected defect by operating someone else's printer. Reproduce with a synthetic file, mocked Moonraker response or a local software-only fixture.

For a vulnerability that could start an unapproved print, leak credentials or cause unsafe motion, use the repository's private vulnerability reporting feature when available. If unavailable, open an issue requesting a private reporting channel without posting exploit details, credentials or live printer addresses.

Include the affected version, minimal synthetic reproduction and expected behavior. Keep real user models, screenshots, tokens and configuration out of public issues. This independent project has no guaranteed response time or physical safety certification.
